# 09 — Natural-Look Rules

Requirement from the owner: nothing on the site, in the code, or in the repository should reveal that machine tools were used to build it. The result must look like the work of a normal web studio. These rules are mandatory in every phase.

## Code and repository
- No comments such as "AI generated", "Generated by", "Here is", "Step 1", "TODO: implement", "Note:" narrations, or explanatory comments that restate the code. Comment only the non-obvious *why*, in short plain English.
- No emojis in code, comments, commit messages, logs, UI text or docs shipped with the site.
- Realistic naming; no `MyComponent`, `Example`, `foo`, `helper2`, `utils_final`. No leftover template files (default Vite logo, `react.svg`, "Vite + React" title, default counter demo, default README text).
- Clean `package.json`: real name (`almubtakirah-website`), version, description in plain words, no template author. Remove unused dependencies.
- `README.md` in the repo: short, human (project, setup, scripts, env vars, deployment). No mention of tools that generated code.
- Do not commit tool folders or logs (`.claude`, `.cursor`, `.agent`, `.gemini`, `.windsurf`, chat exports, `*.log`). Add them to `.gitignore`. Keep the repo private; `AGENTS.md` and `docs/` may live in the repo while it is private, and should be removed from the public bundle (they are not part of `dist`, but double-check).
- Commit messages: short, conventional, written like a developer (`feat(blog): add category filter`). No "AI", no emojis, no co-author trailers of tools.
- No `console.log`, `debugger`, commented-out code blocks.
- Production build: no source maps, minified, no HTML comments left in output, no `generator` meta tag.

## Markup and metadata
- Page `<title>` and descriptions are real and unique; never default titles.
- Sensible DOM: semantic landmarks, no deep `div` soup, no inline style noise, no utility class dumps repeated inline when a component or `@apply` layer is cleaner.
- Favicon, manifest, OG image all branded.

## Visual design
Avoid the "template" look:
- No purple/pink gradients, neon glows, glassmorphism, floating 3D blobs, "sparkle" icons, rainbow gradient text.
- Only the brand palette; gradients only two-color brand gradients.
- No emoji or clip-art icons; single icon set, consistent stroke.
- No symmetrical walls of identical cards with identical icon + 3 lines. Vary layout: split sections, large imagery, lists, numbered processes, tables.
- No fake stats, fake logos, fake testimonials, fake 5-star ratings, fake team photos, fake addresses.
- No stock-photo clichés (handshakes, glowing circuits). Use real work photos when available; otherwise typography and the brand pattern.
- No generic section headings like "Our Amazing Services" / "Why Choose Us?" in English or their literal Arabic equivalents ("لماذا تختارنا؟" is fine only if the surrounding copy is specific). Prefer specific headings, e.g. «صيانة دورية لكل ماركات المصاعد».
- Spacing and type scale consistent; real hover/focus states; no giant rounded corners or heavy shadows everywhere.

## Copywriting (Arabic and English)
- Plain, specific business language written for building owners and facility managers.
- Avoid filler openings: "في عالم يتسارع...", "في عصر التكنولوجيا...", "لا شك أن...", "نحن نقدم لكم أفضل...", "نسعى دائمًا إلى...", "رحلتك نحو التميز". Also avoid in English: "In today's fast-paced world", "elevate", "seamless", "cutting-edge", "unlock", "delve", "game-changer".
- Do not overuse em dashes, rule-of-three lists, and "not only... but also" structures.
- Use concrete nouns and facts from the company profile. If a fact is unknown, omit the sentence.
- Vary sentence length. Keep paragraphs short. Use the company's real terms (مصعد هيدروليكي، وحدة الطاقة، الصمام الرئيسي، الكابينة، الدفاع المدني).
- Blog articles written by staff go through the editor; the first drafts the agent prepares for services must be flagged for human review and should be rewritten in the company's voice.

## Admin UI
Neutral, compact, readable; same brand colors; no decorative illustrations or "welcome" mascots; help text only where useful.
