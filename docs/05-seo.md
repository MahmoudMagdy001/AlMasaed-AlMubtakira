# 05 — SEO Specification (public site)

Target market: Saudi Arabia, Arabic first. Primary city: Jeddah. Locale `ar-SA`, secondary `en`.

## Rendering
Every public page is prerendered (see `03-tech-architecture.md`). Verify with `curl` on the built output: the HTML must contain H1, body text, `<title>`, meta description, canonical, JSON-LD.

## Meta tags (component `<Seo />`, used by every page)
- `<title>`: `{page title} | شركة المصاعد المبتكرة` (≤ 60 chars; home uses a dedicated title).
- `<meta name="description">` 120–160 chars, unique per page.
- `<link rel="canonical">` absolute URL, no trailing slash except root, no query strings. Posts can override via `canonical_url`.
- `<meta name="robots">`: `index,follow` by default; `noindex` for admin, 404, thank-you, search/filter results, empty works page, and posts flagged `robots_noindex`. Preview deployments get `noindex` via `X-Robots-Tag` header.
- Open Graph: `og:type` (`website` / `article`), `og:title`, `og:description`, `og:url`, `og:image` (1200×630), `og:locale` (`ar_SA` / `en_US`), `og:site_name`. Article pages add `article:published_time`, `article:modified_time`, `article:section`, `article:tag`.
- Twitter: `summary_large_image`.
- `<html lang dir>` correct per language. Viewport, theme-color `#132454`.
- No `generator` meta tag. See `09-natural-look-rules.md`.

## hreflang
Every page with an English twin outputs `<link rel="alternate" hreflang="ar-SA" ...>`, `hreflang="en"`, and `x-default` (Arabic). Blog posts link via `translation_key`. Pages without a translation output no hreflang to a missing URL.

## Structured data (JSON-LD, one `<script type="application/ld+json">` per entity)
| Page | Schema |
|---|---|
| Site-wide | `Organization` (name, url, logo, sameAs socials, contactPoint with phones), `WebSite` |
| Home / Contact / About | `LocalBusiness` (use the specific subtype that fits, e.g. `HomeAndConstructionBusiness`; `address` with `addressLocality: Jeddah`, `addressCountry: SA` once street address confirmed; `telephone`, `email`, `areaServed`, `identifier` = CR) |
| Service pages | `Service` (provider → Organization, areaServed Jeddah) + `FAQPage` when FAQ exists |
| Work detail | `CreativeWork` or `Project`-like `Article` with images |
| Blog post | `BlogPosting` (headline, image, datePublished, dateModified, author, publisher, mainEntityOfPage, inLanguage) + `FAQPage` if the post has FAQ items |
| Blog index/category | `CollectionPage` |
| All inner pages | `BreadcrumbList` |
Do not add `aggregateRating`, `Review` or fake ratings. Validate with Google's Rich Results Test.

## Sitemap and robots
- `/sitemap.xml` (index) + child sitemaps if > 500 URLs: static pages, services, works, blog posts, categories. Include `lastmod` from `updated_at`, and `xhtml:link` hreflang alternates.
- Only indexable, published, 200-status URLs. Exclude admin, noindex pages.
- `/robots.txt`: `User-agent: *`, `Allow: /`, `Disallow: /admin`, `Sitemap: https://almubtakirah.com/sitemap.xml`.
- Generated by `scripts/generate-sitemap` after data fetch during the build.

## URLs and redirects
- One canonical host: apex `almubtakirah.com` (no `www`); `www` 301 → apex; HTTP → HTTPS (Vercel does this).
- Lowercase, hyphenated, no trailing slashes, no file extensions.
- Slug change on a published post/work must create a 301 (store in a `redirects` list in `vercel.json` generated at build from a small `redirects` table, or document the manual process). Phase 11 decides and implements one approach.
- Custom 404 returns a real 404 status for unknown paths.

## On-page rules for every page
- Exactly one H1, containing the primary keyword naturally; logical H2/H3 order.
- Internal links: each service page links to related service pages, works, and blog posts; blog posts link to services; breadcrumbs everywhere.
- Images: descriptive Arabic `alt`, width/height set, WebP/AVIF, `srcset`/`sizes`, lazy-load below the fold, LCP image with `fetchpriority="high"`.
- Anchor text descriptive, not "click here".
- Phone numbers as `tel:` links, WhatsApp as `https://wa.me/966559557459`.

## Performance targets (Core Web Vitals)
LCP < 2.5s, INP < 200ms, CLS < 0.1 on mobile 4G. Tactics: prerendered HTML, small JS on public pages, self-hosted fonts with preload, no layout shift from images/fonts (size-adjust fallback), no third-party scripts until consent/GTM, long cache headers for hashed assets.

## Local SEO checklist (for the company after launch, listed in HANDOVER.md)
Google Business Profile (name, category "Elevator service", phone, address, hours, photos, link to site), consistent NAP (name/address/phone) across site, footer, schema, social profiles; collect real reviews; Arabic directories later.

## Content strategy for the blog
Blog categories seeded in the DB. Article topics (starting backlog, written by humans or reviewed by humans): كم تكلفة صيانة المصعد، متى يحتاج المصعد إلى تحديث، علامات تدل على عطل وحدة الطاقة الهيدروليكية، اشتراطات السلامة والدفاع المدني للمصاعد، الفرق بين المصعد الهيدروليكي والكهربائي، ماذا تفعل عند توقف المصعد. Each article ≥ 800 words, one focus keyword, FAQ block, 2+ internal links, original images when possible.
